# Fantrax weekly player-stat acquisition

## Proven 2025/26 method

The historical implementation used authenticated Playwright browser automation, not the developer API. `scrape_allplayers_weekly_fantrax.py` opened the league Players statistics view for one Fantrax period and invoked **Download all as CSV**. `scrape_team_rosters_weekly_fantrax.py` repeated the export for each of 12 fantasy teams. A saved Playwright storage-state file carried the authenticated Fantrax session; login and optional 2FA were completed manually when creating that state.

The all-player file has one stable Fantrax ID per player and the observed schema `ID, Player, Team, Position, RkOv, Status, Opponent, FPts, FP/G, Ros, +/-`. It supplies full-pool identity and authoritative period fantasy points, including free agents, but no advanced events.

The team files are sectioned into Goalkeeper and Outfielder tables. Their proven parsed fields include ID, started slot, player, club, eligible positions, active/reserve status, opponent, fantasy points, GP, GS, minutes, clean sheets, goals against, saves, cards, penalty saves, successful dribbles, tackles won, dispossessions, goals, key passes, assists, interceptions, clearances, aerials, high claims, smothers, own goals, shots on target, accurate crosses, blocks, penalties missed/drawn, and outfield goals against. These advanced fields cover rostered players only.

The legacy workflow skipped existing files in AUTO mode, archived before explicitly forced replacement, and used the scoring-period reference to cap completed periods. Its weaknesses were hard-coded 2025/26 league/team IDs and season URL state, interactive orchestration, no transactional validation across all 13 exports, and no live manifest integration.

## 2026/27 implementation

The live implementation reuses the same authenticated Fantrax CSV interaction but resolves league ID, fantasy-team IDs/names, and authoritative scoring boundaries from the current `getLeagueInfo` cache. It deliberately omits the obsolete hard-coded `SEASON_925_BY_PERIOD` URL token; the 2026/27 league itself establishes season context.

Authentication uses `FANTRAX_AUTH_STATE_PATH` when configured, then the season-scoped `data/raw/fantrax/2627/fantrax_auth_state.json`, then the existing legacy storage-state location for migration compatibility. The storage state is a credential and is never logged or copied into normalized outputs. No browser launches during the preseason empty state or when no periods need acquisition.

For each target period the browser downloads one all-player export and one team export per current `teamInfo` entry. Navigation/download uses a 60-second timeout and up to three attempts with bounded backoff. All files are parsed and validated before any valid cache is replaced.

## Raw cache contract

Each period uses:

```text
data/raw/fantrax/2627/player_stats/period_01/
  all_players.csv
  team_<fantrax-team-id>.csv
  weekly_player_stats.csv
  metadata.json
```

Metadata records period, acquisition status, row count, SHA-256, retrieval time, finalization, unresolved count, validation result, and source. `weekly_player_stats.csv` is the validated cache input consumed by the cache-only build. Original source exports are retained alongside it.

An empty or malformed completed-period response fails before commit. A prior valid cache and all prior model outputs remain usable. A period is finalized when its authoritative Fantrax `scoringPeriods.endDate` is earlier than refresh time and the acquisition validates. Finalized caches are skipped unless an explicit force operation is used.

## Incremental behavior

- Normal Refresh League: acquire missing completed periods only.
- Preseason: return `PRESEASON_NO_PLAYER_STATS`; create no fake rows.
- Nothing new: return `NO_NEW_WEEKLY_DATA`.
- Backfill Weekly Player Stats: acquire all missing completed periods; valid finalized periods are skipped, making it idempotent.
- Force Refresh Current Period: explicitly reacquire the selected/current period. A partial period is marked non-final and excluded from completed-period analytics.

Normal refresh never loops through periods 1–38 blindly.

## Identity, normalization, and source coverage

The all-player export provides the stable Fantrax ID. IDs are stripped of Fantrax's surrounding `*` markers and joined exactly through Player Registry. No fuzzy production match exists. Eligible multi-position strings are retained.

The scoring-category coverage matrix is generated by joining the real league scoring dictionary to normalized weekly coverage. The team source contains every short-name category presently mapped by the league dictionary: KP, AER, CLR, CoS, DIS, G, OG, Int, GA, HCS, PKS, RC, Sv, SOT, CS, TkW, Sm, YC, AT, AC, BS, GAO, GS, Min, PKD, PKM, SBON, and SBOF. Fantasy points come from both exports, with the roster export winning for rostered players. Total shots, fouls, and other columns not present in the source remain missing unless approved Understat supplementation applies.

Explicit zero is a valid observation and is counted separately from missing coverage.

## Rosters and submitted lineups

Historical `getTeamRosters?period=N` responses provide period-specific ACTIVE/RESERVE/IR state and roster-slot position. `manager_player_weekly` joins on player ID plus period; current ownership is never applied retroactively. Historical manager facts are available only for roster periods actually cached. Backfilling player statistics alone cannot recreate an uncached historical submitted lineup.

## Reconciliation

Before matches, player/manager/season score reconciliation has no factual target and remains intentionally empty. Once weekly values exist, validation reports weekly normalized fantasy points, source row counts, duplicates, Ghost component availability, and scoring-category coverage. Differences from matchup/manager totals are reported rather than corrected. Understat never fills fantasy points or Ghost inputs.
